================================================================================
WHAT THE SETUP DOES
================================================================================

The scripts automate creation of these 5 AWS resources:

1. OIDC PROVIDER
   - URL: https://oidc.vercel.com/leoemaxie
   - Purpose: Tells AWS to trust Vercel
   - Created in: AWS IAM Console

2. IAM ROLE
   - Name: vercel-noa-app-role
   - Purpose: Grants permissions to your app
   - Trust policy: Only Vercel can assume this role

3. DYNAMODB POLICY
   - Permissions: Read/write patient data
   - Resources: noa-data table + all indexes
   - Actions: GetItem, PutItem, Query, Scan, etc.

4. BEDROCK POLICY
   - Permissions: Call AI models
   - Resources: Nova Lite, Nova Pro, Claude
   - Actions: InvokeModel, InvokeModelWithResponseStream

5. DYNAMODB TABLE
   - Name: noa-data
   - Primary key: id (String)
   - Global Secondary Indexes:
     • email-index (query by email + type)
     • doctorId-index (query by doctor + type)
     • patientId-index (query by patient + type)
   - Billing: On-demand (pay only for usage)

================================================================================
HOW IT WORKS
================================================================================

Old way (fails with InvalidIdentityToken):
  Your app tries to access AWS
    → Looks for AWS credentials in environment
    → AWS doesn't trust the request
    → Error: InvalidIdentityToken
    → Request fails ✗

New way (after setup):
  Your app tries to access AWS
    → @vercel/functions/oidc gets token from Vercel
    → Vercel token is verified by AWS OIDC provider
    → AWS issues temporary credentials (1 hour)
    → App uses credentials to access DynamoDB/Bedrock
    → Request succeeds ✓
    → Credentials auto-expire

Security benefits:
  ✓ No stored credentials anywhere
  ✓ Automatic rotation every hour
  ✓ AWS knows exactly who's asking (Vercel project ID)
  ✓ Fine-grained permissions per app
  ✓ Easy to revoke (delete the role)
